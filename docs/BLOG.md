# Блог: как заливать статьи

Инструкция для тех, кто публикует статьи на philgodlewski.link — по одной или пачками. Цель блога — приводить людей из поиска и вести их в каналы Фила (Telegram, Rumble, Instagram, Threads, Locals), поэтому у каждой статьи внизу есть блок «Follow Phil Godlewski».

## Одна статья = один файл

`src/content/blog/<slug>.md`. Имя файла — адрес: `ai-in-sports-scouting.md` → `/blog/ai-in-sports-scouting`.

- slug: латиница, нижний регистр, слова через дефис, до 75 символов, без дат и ID;
- после публикации slug не менять. Если всё же сменили — старый адрес добавить в `aliases` (будет 301).

Быстрый старт: `npm run new-post -- "Article title" --category ai --tags "ixo, future-of-money"` создаёт файл-черновик с шапкой. Все поля с пояснениями — в `src/content/blog/_TEMPLATE.md`.

## Шапка (frontmatter)

| Поле | Обязательно | Правило |
|---|---|---|
| `title` | да | ≤ 70 символов. Это H1 страницы и основа `<title>` |
| `description` | да | 50–170 символов. Meta description, превью в соцсетях и карточках |
| `pubDate` | да | `YYYY-MM-DD`. Будущая дата — статья появится при первой сборке после неё |
| `category` | да | id рубрики: `technology`, `sports`, `ai`, `design`, `ventures` (или новая, см. ниже) |
| `tags` | нет | 2–5 тегов, только id из списка `src/content/tags.yml` (см. «Теги» ниже) |
| `seoTitle` | нет | ≤ 60 символов, если `<title>` для поиска должен отличаться от заголовка |
| `updatedDate` | нет | дата существенного обновления — показывается на странице и в sitemap |
| `cover` + `coverAlt` | нет | обложка из `src/assets/blog/`, путь от файла статьи: `../../assets/blog/<slug>.jpg`. `coverAlt` обязателен |
| `cta` | нет | какой канал выделить после статьи: `telegram` (по умолчанию), `rumble`, `instagram`, `threads`, `locals` |
| `faq` | нет | список `q`/`a` — блок вопросов в конце статьи и разметка FAQPage для Google |
| `featured` | нет | `true` — в блоке Recommended на `/blog` (берутся 3 самых свежих) |
| `related` | нет | id статей вручную; иначе похожие подбираются по рубрике и тегам |
| `aliases` | нет | старые адреса этой статьи → 301 |
| `noindex` | нет | `true` — закрыть от поисковиков |
| `draft` | нет | `true` — черновик: виден в `npm run dev`, на сайт не попадает |

Если шапка заполнена неправильно, `npm run build` падает и пишет, какой файл и какое поле не так.

## Текст

- Заголовки начинаются с `##` (H2), дальше `###`, `####`, уровни не пропускать. `#` не использовать — H1 уже есть.
- Картинки — в `src/assets/blog/`, вставлять `![осмысленный alt](../../assets/blog/file.jpg)`. При сборке они сжимаются в WebP и получают нужные размеры.
- Ссылки на другие статьи блога — относительные: `[текст](/blog/other-slug)`. Перелинковка между статьями одной темы помогает и поиску, и читателю.
- Ссылку на каналы Фила в текст можно ставить обычной ссылкой — переход всё равно посчитается в аналитике как `social_click`.
- Таблицы и код в Markdown поддерживаются, на телефоне прокручиваются внутри блока.

## Пакетная заливка

1. Подготовить файлы статей по правилам выше (можно генерировать скриптом), картинки положить в `src/assets/blog/`.
2. `npm run build` локально — сборка проверит все шапки разом.
3. `npm run preview` — посмотреть результат на http://localhost:4321.
4. Коммит и push в `main`. Сайт пересоберётся сам примерно за минуту.

Разносить `pubDate` по дням для отложенной публикации можно, но такие статьи появятся только при следующей сборке после их даты.

## Рубрики

Файл `src/content/categories/<id>.md`:

```md
---
name: Ventures
description: '50–170 символов: карточка рубрики и meta description'
seoTitle: 'до 60 символов, <title> страницы рубрики'
order: 5
---

Вступительный абзац на странице рубрики.
```

- Добавить рубрику — добавить файл. Страница `/blog/category/<id>` появится, когда в рубрике будет хотя бы одна статья.
- Удалить рубрику — удалить файл. Если на неё ещё ссылаются статьи, сборка упадёт и перечислит их: сначала перенесите статьи в другую рубрику.
- Переименовать рубрику — поменять `name`, id (имя файла) не трогать, иначе поменяются адреса.

## Теги

Теги — закрытый список в `src/content/tags.yml`. В статье указывается **id** тега, а на сайте показывается его название:

| id | Название |
|---|---|
| `privacy` | Privacy |
| `ixo` | IXO |
| `ai-in-practice` | AI in Practice |
| `blackrock-aladdin` | BlackRock & Aladdin |
| `holder-access` | Holder Access |
| `regulation` | Regulation |
| `future-of-money` | Future of Money |
| `2020-election` | 2020 Election |
| `eo-13848` | EO 13848 |
| `shadow-power` | Shadow Power |
| `elections-power` | Elections & Power |
| `q-codes` | Q Codes |
| `arrests-emergency` | Arrests & Emergency |
| `media-critics` | Media & Critics |
| `faith-prophecy` | Faith & Prophecy |
| `blogger-community` | Blogger & Community |
| `atom` | ATOM |

Пример: `tags: ['ixo', 'future-of-money']`.

- Тег не из списка или опечатка — сборка падает и называет статью.
- Добавить тег — дописать в `tags.yml` пункт `- id: …` / `name: …`. id: латиница, нижний регистр, дефисы; это адрес `/blog/tag/<id>`, после публикации не менять.
- Можно добавить `description:` (50–170 символов) — он станет вступлением и meta description страницы тега.
- Страница тега появляется, когда у него есть хотя бы одна статья; в поиск Google она открывается с 3 статей.
- Удалить тег — убрать пункт; если он ещё стоит в статьях, сборка упадёт и перечислит их.

## Авторы

`src/content/authors/<id>.md` (по умолчанию все статьи от `phil-godlewski`). Другой автор — поле `author: <id>` в шапке статьи.
